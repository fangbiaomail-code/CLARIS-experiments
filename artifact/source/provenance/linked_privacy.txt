CLARIS: identity privacy for a disclosed selected component
Prepared for integration into JSA_manuscript.tex, 2 October 2026.
This file proves a modular extension of the existing privacy result. It does not certify the two implemented proof systems or their quantum properties.

1. What can be proved

The original unselected-report game does not permit a challenge link and therefore does not imply anonymity of a disclosed set. The following challenge-pool experiment does. The adversary can receive a complete selected-link certificate and can adaptively request further, overlapping selections among challenge reports. All challenge reports have the same hidden owner. That common-owner fact is intentionally public; the protected bit is which of two eligible registered users is that owner.

The result can cover a fixed batch of challenge reports, or a polynomial number of fresh challenge reports added through the special challenge-report interface below. It does not permit importing an ordinary report already labelled with a known owner into the protected pool. It also does not protect a component after a claim naming one of its owners, or after an accepted bridge to an owner-labelled report. Those disclosures logically reveal the bit and cannot be covered by a meaningful anonymity theorem.

2. Experiment ComponentAnon_b

Setup follows the same honest static-registry model as the manuscript. Fix two distinct registered candidates u_0,u_1 and one public ring R containing both. Candidate nomination is public and independent of b. Neither candidate may be corrupted before or after nomination. If nomination is adaptive after a prechallenge view, the tuple-pseudorandomness advantage used below must be the adaptive-target version with precisely that view; a selective-target assumption alone is insufficient without a target-selection reduction loss.

Maintain an ordinary issuance log O and a protected issuance log C. Each protected record has a public opaque handle, its exact record bytes, its report statement q_r, and a hidden owner u_b. It does not acquire a public identity label. The experiment implements these classical-request interfaces:

(i) Report(u,R',m), Claim(u,r), Link(u,S), Corrupt(u): the manuscript's ordinary services, with the following additional public rule. Claims and named-user links refuse any protected record or any record retaining a protected report statement q_r, for both b=0 and b=1. They also reject records absent from the relevant ordinary issuance log, as already required by the manuscript. Candidate corruptions are disallowed. On all remaining records, including ordinary reports issued for either candidate, the normal services remain available. Their ownership labels and authorization decisions are the same in both experiments.

(ii) ChallengeReport(m): create a fresh honest report under (u_b,R,m), add it to C, and return the record and its handle. The adversary supplies one message, rather than different messages for the two worlds. Equivalently, a fixed-batch challenge supplies a list of messages and performs this operation a fixed number of times.

(iii) ProtectedLink(S): S is an ordered selection of at least two exact report instances from C. Check the same public conditions as Link: the common manifest, distinct references, disjoint input blocks, and accepted original proofs. If they pass, generate the normal CLARIS link using k_{u_b}, with c_S = H_selected(s,rid(r_0),...,rid(r_{s-1})). Otherwise return bottom. No identity index is accepted by or returned from this interface. Repeated and overlapping selections are allowed, and the selection can depend on the whole previous view. Every edge uses the entire ordered selection context, exactly as in the construction.

The ordinary disclosure interfaces cannot be used to ask whether a protected record belongs to u_0 or u_1: both requests return bottom by the same protected-record rule. ProtectedLink does not perform an identity-indexed authorization test; authorization follows from membership in C. It recomputes the public conditions and, in the real experiment, uses the unique challenge key to generate the ordinary certificate. As usual the adversary may freely run all public verification algorithms and construct candidate certificates on its own.

The advantage is |Pr[ComponentAnon_0(A)=1] - Pr[ComponentAnon_1(A)=1]|. Queries that violate the experiment's corruption rule are treated as inadmissible, or are rejected identically in both worlds. Any implementation of this game must use the same convention in both worlds.

Interpretation. This game hides the owner of every connected component formed by ProtectedLink certificates; in fact the whole challenge pool uses one hidden owner. Overlapping selections may deliberately reveal that a larger component has a common source. The adversary learns the selected lists, all public report data, and these equal-owner facts. It does not learn whether the hidden owner is u_0 or u_1. Ordinary claims on unrelated reports of u_0 or u_1 remain allowed. Their relevance to the protected records must stay cryptographically hidden, as covered by the joint PRF assumption and simulation argument.

3. Required assumptions and bad events

Use the manuscript's joint adaptive multi-theorem simulation property for the tagged union (Pi_Q,Pi_G), with total error eta_Z at the enlarged experiment budget. This hop covers every issued report proof, ordinary claim, ordinary link edge, and protected link edge. If only a per-proof error delta_Z is available, eta_Z must include the corresponding hybrid sum over all these proofs; the theorem does not grant a proof-count-independent concrete error.

The simulator is a statement-only algorithm. Its executable extension and its shared public-oracle controller must be defined on the hybrid statements obtained by replacing the candidates' AES tuples. Such statements may be false for concrete AES. Ordinary true-statement ZK by itself does not provide this extension. All visible simulator outputs, oracle programming, state updates, public verification outcomes, and any simulator failure depend only on the public statement/history and the controller's randomness, not on b, the hidden owner label, or an unavailable candidate key. For QPT security, this requirement is for one quantum-compatible public-oracle channel shared by both proof roles. A classical rewinding simulator does not satisfy it automatically.

Define epsilon_F for replacing BOTH candidates' entire joint public/report evaluation interfaces by independent hidden random functions f_0,f_1. Public-key evaluations at X_P and all ordinary/protected report evaluations use these same two functions, with repeated inputs answered consistently. Preserve the real public cipher interface and all noncandidate keys/evaluations. The advantage includes this actual auxiliary view and the executable public simulator/controller; it is not bare single-tag PRF security. It must also include candidate selection if adaptive nomination is permitted. Random functions are a model change from AES permutations: the chosen epsilon_F includes the PRP/PRF switching contribution at the total evaluation budget if deriving it from a permutation assumption.

Let epsilon_B^C bound the following events in the relevant hybrids, including final assessment and all service overhead:
  - context/reference collisions, repeated honest nonces, or ambiguous encodings;
  - a protected input point that was previously evaluated by either candidate's ordinary report service;
  - a new protected tuple intersecting any earlier protected tuple;
  - a later ordinary report evaluation of either candidate at a protected input point.
The public-key input prefix differs from report inputs, so public-key points cannot produce these intersections. Public revelation of X_r itself is NOT a bad event; X_r is intentionally public. Direct adversarial evaluation of AES under guessed keys belongs to the public-cipher/PRF experiment and is not silently excluded by the freshness rule. Adaptive attempts to force overlapping hash-derived inputs must be bounded in epsilon_B^C using the appropriate classical or quantum expansion budget. Do not condition the experiment on future absence of overlap; the proof stops online at its first occurrence.

ProtectedLink does not add fresh keyed evaluation points: it compares already issued tuples. In the simulated experiment, its witness checks are supplied by the protected issuance log and public conditions; the statement-only simulator need not know a candidate key. Equal accept/refuse bits follow from these explicit rules. Merely asserting equal bits without defining this interface would miss the trivial identity-test attack through Link(u_0,S).

4. Theorem

Under the joint simulation and tuple-pseudorandomness interfaces above, for any admissible adversary making polynomially many challenge reports and protected-link queries,

  Adv_ComponentAnon <= 2(eta_Z + epsilon_F + epsilon_B^C).

The quantities are evaluated at this experiment's augmented budgets. The theorem holds for PPT adversaries if all premises hold classically, and for QPT adversaries only if the premises and public-oracle controller hold in the corresponding quantum model. No extraction assumption or eta_E term is required for this privacy result. Soundness and binding are used separately to justify the ownership meaning of arbitrary accepted adversarial certificates.

5. Proof

Fix b. Let G_b be the real experiment. First replace every honest proof by the joint statement-only simulation to obtain H_b, at distinguishing cost at most eta_Z. This hop is invoked only on true service statements: all ordinary services have valid logged keys, all protected reports use u_b, and all protected links refer to records honestly issued using that same key. A reduction proving this ZK hop generates the registry and supplies the valid witnesses to the witness-checked simulation experiment. Subsequent contexts and record identifiers are recomputed from the newly returned proof bytes, as required by the actual protocol; the adaptive multi-theorem experiment includes those dependent future statements.

Next replace the candidates' joint public/report evaluations by f_0,f_1, obtaining J_b, at cost at most epsilon_F. The public executable simulator/controller makes this step well defined even when the resulting report, claim, or edge statements no longer have concrete AES witnesses. Ordinary service authorization uses its labelled issuance log. Protected-link authorization uses C. Thus no unknown candidate key is needed to compute a service decision in J_b. This is precisely why the specified auxiliary-interface version of epsilon_F suffices.

Couple J_0 and J_1 online. Use identical noncandidate keys and outputs, public parameters, setup randomness, initial simulated-oracle state, and adversary randomness/quantum state. Give each named candidate the same lazily sampled values in both worlds at all public-key inputs and ordinary service points. Public registries and the ordinary disclosure history consequently agree. The candidates' hidden functions remain distinct within each world.

On a new protected report request, use identical message, nonce, expansion responses, and hence identical c_r and X_r. If X_r intersects a previously exposed candidate input or an earlier protected input, stop the coupling and charge the event to epsilon_B^C. Otherwise choose a fresh independent four-block vector Y. Set f_0(X_r)=Y in J_0 and f_1(X_r)=Y in J_1, point by point. Leave the unused candidate's values at these points unsampled. This is a valid coupling: in each marginal experiment the four fresh function values are independent uniform values, and the same hidden candidate is used for every protected report in that experiment. All candidates' ordinary evaluations at disjoint points retain their own consistent tables. Thus the proof preserves shared-key correlation instead of assigning inconsistent independent functions to individual records.

The report public statement is now the same in both worlds. Run the same public simulator and oracle controller with shared randomness; obtain the same proof bytes, and compute the same full instance identifier including those bytes. Insert the same public record/handle into C in each world, with only its hidden owner label differing.

On ProtectedLink(S), the adversary's state and view are the same until stopping, so its request distribution is the same. Both worlds contain the same exact selected records. All structural and verification checks, the full ordered selection context, and each pair of endpoint tuples are therefore identical. The same public simulator/controller yields identically distributed edge proofs and states. This argument applies to the first disclosed set, to subsets, to reordering, and to arbitrary adaptive overlap between previously disclosed selections. The full-list context changes consistently in both worlds; reusing an endpoint in several proofs introduces no new hidden-function sample. The argument also permits a fresh ChallengeReport after previous links, followed by links including that new report.

On an ordinary report request for either candidate, stop before answering if an input intersects a protected point. Otherwise use common fresh lazy samples or previously common ordinary samples for that named candidate. An ordinary claim or link uses identical nonprotected records and common owner labels. Both worlds have the same authorization and public verification decisions, and all proofs are simulated from identical public statements. A named-user disclosure touching a protected statement refuses in both worlds. Other corruptions reveal the same keys; candidate corruptions are inadmissible.

Consequently the coupled views agree until the first stopping event. For a quantum adversary this conclusion concerns the full state: all public oracle operations are the same channel because the public controller and statements are identical, while the two hidden candidate functions are accessed only through classical application requests. One must not give the adversary a coherent oracle for the hidden candidate functions and then reuse this classical-table coupling without a new proof. Real public cipher queries are already accounted for by epsilon_F.

The two stopped hybrids have identical output distributions. Departing from the stopped process costs at most epsilon_B^C in each marginal. Applying the triangle inequality to G_0 -> H_0 -> J_0 -> J_1 -> H_1 -> G_1 gives 2 eta_Z + 2 epsilon_F + 2 epsilon_B^C, as claimed. The argument uses no future-dependent conditioning and no extraction.

6. Scope and nonextensions

Supported: a fixed selected set; full disclosure of its link certificate; repeated linking of that set; adaptively chosen and overlapping subsets; fresh protected-report extensions through ChallengeReport; ordinary reports/claims/links on unrelated logged records, including those of either candidate.

Not proved: retroactive absorption of arbitrary pre-existing records with externally known owners; links to an ordinary known-owner record; a claim anywhere in the protected component; candidate key corruption; hiding which reports the user selected; traffic-analysis/metadata privacy; arbitrary graph leakage constrained only by an informal policy. For example, if r_ext was returned by Report(u_0,R,m), a service that accepts Link((r_star,r_ext)) iff r_star has that owner exposes b through its accept/refuse bit. If it gives an accepted certificate, the certificate plus the known owner also exposes b. Likewise Claim(u_0,r_star) must not be an identity-testing oracle.

The protected-pool game has an explicit identity-independent authorization boundary. It is stronger than the current unselected-report theorem and suitable for the paper's statement that a disclosed same-owner set can remain identity-hidden. It is narrower than a general leakage-based anonymity game for arbitrary evolving disclosure graphs. The manuscript should name it component anonymity / challenge-pool anonymity and state the boundary, rather than claim arbitrary disclosure-composable anonymity.

7. Suggested concise manuscript insertion

Definition (Selected-component anonymity). Two uncorrupted candidates u_0,u_1 belong to the same ring. A challenge-report service issues reports using u_b and records them in a protected pool. An identity-free protected-link service returns ordinary CLARIS certificates for any admissible ordered selection entirely within that pool, allowing adaptive overlapping selections. Named-user claim and link services refuse protected report statements in both worlds, and candidate corruptions are forbidden. Ordinary report and disclosure services remain available on all other issued records, including those of either candidate. A protected component is never claimed or connected to an ordinary owner-labelled report. Its anonymity advantage is the difference of the two challenge worlds' output probabilities.

Theorem (Selected-component anonymity). Under the same joint public simulation and candidate-key pseudorandomness interfaces, at the enlarged report/proof budgets, Adv_component <= 2(eta_Z+epsilon_F+epsilon_B^C), where epsilon_B^C includes intersections between protected inputs and ordinary candidate evaluations and repeated protected inputs. This covers adaptive overlap within the protected pool and fresh challenge-report extensions.

Proof paragraph. Simulate all report and disclosure proofs, and replace both candidates' complete public/report evaluation interfaces by hidden random functions. In each world the whole protected pool uses one candidate function. Couple its fresh input values across worlds, while keeping the named candidates' ordinary values common at all other inputs. Each resulting report statement, simulated proof, full report identifier, selected-list context, and link-edge statement is then identical in the two worlds. Protected-link authorization depends only on the protected issuance log; other authorization decisions use common ordinary owner labels. Stop online if an ordinary candidate evaluation exposes a protected point, a new protected tuple overlaps an earlier one, or another binding/freshness bad event occurs. Before stopping the public proof controller gives the same classical or quantum oracle channel, including after overlapping link queries. Each world incurs eta_Z+epsilon_F+epsilon_B^C, giving the bound. A claim or a link to an owner-labelled record deliberately exits this experiment's privacy guarantee.
